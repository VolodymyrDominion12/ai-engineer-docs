## Додаток B. Зведені таблиці: моделі, ціни, ліміти

Це **знімок даних станом на 26.09.2026**. Числа не переказують розділи, а зводять їх в одне місце:
щоб порівняти моделі, ціни, ліміти й розміри системних промптів, не гортаючи двадцять п'ять розділів.

**Правило цього додатка: кожне число має джерело.** Джерело вказано рядком під заголовком кожної
таблиці, а зведена карта «таблиця → файл → URL» наведена в підрозділі B.12. Нічого не додано з
пам'яті чи з оцінки; рядок, якого немає в джерелі, тут не з'явився. Якщо джерело містить прочерк,
у таблиці стоїть прочерк.

Ціни всюди — долари США за **мільйон токенів** (MTok), якщо не вказано інше. Деякі джерельні
документи вже оновлювалися після збору; перед використанням у бюджеті звіряйтеся з первинним URL.

### B.8 HTTP-коди помилок і що з ними робити

**Джерело:** `research/02/overload.md` — https://platform.claude.com/docs/en/api/errors.md

| Код | Тип помилки | Що сталося | Дія |
|---|---|---|---|
| 400 | `invalid_request_error` | Проблема з форматом або вмістом запиту. Також повертається при досягненні встановленого ліміту витрат організації чи простору | Виправити запит; не ретраїти |
| 401 | `authentication_error` | Проблема з ключем API: некоректний, відкликаний або протермінований | Замінити ключ; не ретраїти |
| 402 | `billing_error` | Проблема з платіжною інформацією | Перевірити платіжні дані; не ретраїти |
| 403 | `permission_error` | Ключ не має прав на цей ресурс | Перевірити права й налаштування простору; не ретраїти |
| 404 | `not_found_error` | Ресурс не знайдено | Перевірити шлях і ідентифікатори; не ретраїти |
| 409 | `conflict_error` | Конфлікт зі станом ресурсу, наприклад конкурентна зміна | Розв'язати конфлікт і повторити |
| 413 | `request_too_large` | Перевищено максимум байтів для ендпоінта | Зменшити запит; не ретраїти як є |
| 429 | `rate_limit_error` | Ліміт швидкості, місячна стеля витрат тіру або ліміт простору | Ретраїти з відкатом; для стелі витрат заголовка `retry-after` немає |
| 500 | `api_error` | Неочікувана внутрішня помилка | Ретраїти з експоненційним відкатом; при повторенні — у підтримку з `request_id` |
| 504 | `timeout_error` | Таймаут обробки | Ретраїти; для довгих запитів перейти на стрімінг або батч |
| 529 | `overloaded_error` | API тимчасово перевантажено | Ретраїти з відкатом |

Офіційні SDK самі повторюють тимчасові збої з експоненційним відкатом — типово **двічі**, із
повагою до заголовка `retry-after`. Кожен клієнт приймає опцію максимальної кількості повторів.
У стрімінгу помилка може прийти **після** відповіді 200, подією `error`, тому обробка там не
підпадає під цю таблицю.

### B.10 Ліміти батч-обробки

**Джерело:** `research/02/batches.md` — https://platform.claude.com/docs/en/docs/build-with-claude/batch-processing.md

| Параметр | Значення |
|---|---|
| Максимум запитів у батчі | 100 000 запитів або 256 МБ, що настане раніше |
| Типовий час завершення | Більшість батчів завершується протягом 1 години |
| Строк очікування результатів | 24 години; якщо обробка не завершилася, батч протерміновується |
| Зберігання результатів | 29 днів після `created_at`, а не після `ended_at` |
| Максимум вихідних токенів за бета-заголовком `output-300k-2026-03-24` | 300 000 токенів на Opus 5, Opus 4.8, Opus 4.7, Opus 4.6, Sonnet 5, Sonnet 4.6 |
| Знижка на всі запити батчу | 50% від стандартних цін API |
| Типи результатів | `succeeded` (єдиний платний), `errored`, `canceled`, `expired` |
| Влучання в кеш усередині батчу | Режим без гарантії: типово від 30 до 98 відсотків |
| Що не підтримується | `stream: true`, `max_tokens: 0` (прогрів кешу) |
| Скасування | `processing_status` дорівнює `canceling`, потім `ended` із частковими результатами |

Обмеження витрат простору можуть бути трохи перевищені: через високу пропускну здатність і
паралельну обробку батчі іноді виходять за налаштовану межу. Ліміти швидкості діють і на HTTP-запити
Batches API, і на кількість запитів усередині батчу, що чекають обробки. Батчі обмежені межами
робочого простору.
