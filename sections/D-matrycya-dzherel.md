## Додаток D. Матриця «джерело → розділ»

Цей додаток показує, на яких первинних джерелах побудований кожен розділ, і скільки джерел
залишилося поза матрицею. Мета — зробити покриття **перевірюваним**: щоб можна було побачити, які
твердження мають під собою джерело, а які — ні.

### D.1 Як побудована матриця

Матриця генерується програмою, а не заповнюється вручну. Метод:

1. Кожен файл у `research/` починається рядком `### SOURCE: <URL>`.
2. Скрипт витягує ці URL і шукає їх серед markdown-посилань у файлах `sections/`.
3. URL нормалізуються: прибирається схема, хвостовий слеш і суфікс `.md`.

Відтворити:

```bash
python3 tools/source_matrix.py              # підсумок по розділах
python3 tools/source_matrix.py --markdown   # готовий блок таблиці
python3 tools/source_matrix.py --orphans    # джерела поза матрицею
```

### D.3 Обмеження методу — читайте перед використанням

**Ці числа — нижня оцінка, а не повний перелік.** Автоматичне зіставлення за URL промахується з
двох причин:

1. **Розбіжність URL.** Хедер джерела містить URL, яким його завантажив `fetch.py`, — іноді з
   суфіксом `.md` або зі шляхом `/docs/en/docs/`. У тексті розділу посилання веде на канонічний URL
   без `.md` і з іншим шляхом. Обидва URL працюють, але текстурно не збігаються.
2. **Посилання в прозі.** Частина розділів посилається на джерело лише словесно («за документацією
   Anthropic»), без URL. Такі зв'язки не знаходяться взагалі.

Приклад розбіжності: розділ 7 (мультимодальність) побудований на чотирьох джерелах (`vision.md`,
`pdf.md`, `citations.md`, `files-api.md`), але в матриці показано 2 — бо в тексті посилання ведуть
на `https://platform.claude.com/docs/en/build-with-claude/...`, а збережені файли мають хедер із
`https://platform.claude.com/docs/en/docs/build-with-claude/....md`.

**Практичний висновок:** для оцінки «чи має розділ джерела» ця матриця придатна. Для перевірки
конкретного твердження — дивіться блок **Джерела** в кінці розділу, він авторитетніший.

### D.4 Що поза матрицею

Поза матрицею залишається більше джерел, ніж у ній. Це **не** означає, що вони невикористані —
категорії різні:

| Категорія | Що це | Приклади |
|---|---|---|
| **Індекси документації** | Переліки всіх сторінок для навігації | `02/_index_claude_llms.txt`, `02/_index_openai_api_llms.txt` |
| **Знімки API** | Метадані моделей із Hugging Face, версії з PyPI | `hf_*.json`, `pypi_*.json` |
| **Сирці бібліотек** | Реальний код, а не документація | `hf5src/*.py`, `quant/ggml_h.txt` |
| **Скрипти збору** | Хелпери, не джерела | `research/*.py` |
| **Джерела розділів у роботі** | Завантажені, але розділ ще не написано | `research/13/*`, `research/22/hf_jobs_guide.md` |
| **Резервні джерела** | Завантажені для перевірки, але не процитовані | `econ/*_pricing.txt` |

Переглянути повний перелік:

```bash
python3 tools/source_matrix.py --orphans
```

Остання категорія — найцікавіша для контролю якості. Якщо джерело завантажене «для розділу», але не
згадане ні в розділі, ні в ноутбуку, це або резерв, або ознака, що частина дослідження не потрапила
в текст. Перевірка займає хвилину й іноді виявляє прогалини.
