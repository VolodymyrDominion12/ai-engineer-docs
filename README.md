# AI Engineer — довідник українською

Практичний довідник з AI-інженерії для досвідчених Python-розробників. Пояснює не лише «як викликати
API», а й **що відбувається під капотом**: як рахуються токени, чому кеш не влучає, як влаштований цикл
агента, скільки пам'яті з'їдає квантизована модель.

**Зріз даних:** 26 вересня 2026 року.
**Мова:** українська; англійські терміни в дужках при першій згадці.
**Аудиторія:** Python-розробник (≈10 років досвіду), який щойно входить у AI.

---

## Головний принцип проєкту

> **Жодної назви моделі, ціни, назви параметра чи версії бібліотеки «з голови».**

Кожна така деталь підтверджена первинним джерелом — офіційною документацією, сторінкою релізу або
PyPI, — і збережена в `research/`. Це принципово, бо екосистема LLM змінюється швидше, ніж будь-яке
друковане видання: знання моделі «з пам'яті» тут майже завжди застарілі.

Якщо факт не вдалося підтвердити, у тексті так і написано: *«не вдалося підтвердити станом на 09.2026»*.

## Швидкий старт

```bash
git clone git@github.com:VolodymyrDominion12/ai-engineer-docs.git
cd ai-engineer-docs

# Середовище для ноутбуків

source .venv/bin/activate

# Мінімум для ноутбуків без GPU (усі ноутбуки виконуються без GPU; GPU потрібен
# лише для реального завантаження моделей у розділах 19–21)
pip install -r requirements.txt

# Ключі — лише через .env, ніколи в коді
cp .env.example .env
$EDITOR .env

jupyter lab
```

Ноутбуки **3, 6, 7, 9, 12, 14** виконуються повністю **без жодного API-ключа** — з них і варто
починати. Решта працюють без ключа, але клітинки з реальними викликами API друкують повідомлення
про пропуск.

**Про GPU.** Ноутбуки 19, 20, 21 (Transformers, квантизація, fine-tuning) **виконуються й без GPU** —
усі клітинки, що завантажують модель, захищено `try/except`, а обчислювальна частина (аналіз сирців,
арифметика пам'яті) працює на стандартній бібліотеці. GPU потрібен лише для того, щоб реально
завантажити й запустити модель. Вимоги вказано в першій markdown-клітинці кожного ноутбука.

### Ноутбуки збираються програмно

Ноутбуки не редагуються вручну — вони генеруються через `nbformat`, щоб текст і код не розходилися:

```bash
# Зібрати всі ноутбуки (або вказати конкретний: 03)
python3 tools/build_notebooks.py
python3 tools/build_notebooks.py 03

# Перевірити, що ноутбук справді виконується без ключів
python3 -m nbconvert --to notebook --execute --inplace notebooks/03-tokenizaciya.ipynb
```

Ноутбук, який падає без API-ключа там, де заявлена робота без ключа, — це дефект, а не очікувана
поведінка. Кожен ноутбук закінчується клітинкою самоперевірки з `assert`-ами.

### Головний редактор

`BRIEF.md` вимагає, щоб кожен розділ мав заголовок рівно `##`, а зміст робив «головний редактор».
`tools/build_book.py` — це той редактор: він збирає всі розділи й додатки в один `BOOK.md`, генерує
титульну сторінку й зміст із якорями, і **перевіряє структуру** кожного файлу:

| Перевірка | Рівень |
|---|---|
| Власний `# H1` у файлі розділу | ✗ помилка |
| Відсутній або дубльований заголовок `##` | ✗ помилка |
| `####` без жодного `###` (стрибок рівня) | ✗ помилка |
| Відсутній блок «Джерела» | ⚠ попередження |

Розділення на помилки й попередження зроблено навмисно: відсутність блоку «Джерела» для
додатка-глосарія нормальна, а для розділу — ні, але документ вона не ламає.

При збірці рівні заголовків **підвищуються на один** (`##` → `###`), щоб зберегти вкладеність під
`# H1` документа. `BOOK.md` — генерований артефакт, він у `.gitignore`: джерело істини — `sections/`.

Прапорець `--check-shadowing` існує тому, що затінення імен — найчастіша тиха помилка в ноутбуках:
клітинки виконуються в одному namespace, і змінна-об'єкт, перевикористана як ціль циклу в іншій
клітинці, тихо затирає об'єкт. Саме так виникли три помилки під час написання цього довідника.

`audit_sources.py` — запобіжник проти дефекту, який у цьому проєкті виникав двічі: невдале
завантаження осідало у файлі, який виглядав як справжнє джерело. `fetch.py` тепер друкує помилки в
**stderr**, тож `python3 fetch.py URL > файл` більше не створює файл із текстом помилки.

### Виводи ноутбуків зберігаються при перезбірці

Перезбірка ноутбука з модуля створює клітинки **без виводів**. Для довідника це регресія: читач має
бачити очікуваний результат, не запускаючи код. Тому збирач **переносить виводи** з наявного файлу
для тих клітинок, джерело яких не змінилося, і очищує їх лише для змінених (ті все одно застаріли).

Практичний наслідок: після правки модуля запускайте виконання, інакше змінені клітинки залишаться
без виводу:

```bash
python3 tools/build_notebooks.py 25     # перезбірка (виводи незмінених клітинок збережено)
timeout 500 python3 -m nbconvert --to notebook --execute --inplace notebooks/25-serviing.ipynb
```

### Правила написання клітинок

Модуль ноутбука тримає клітинки як рядкові літерали, і Python обробляє escape-послідовності
**двічі**. Це джерело чотирьох реальних помилок у цьому проєкті. Повний перелік правил — у
docstring `tools/nbkit.py`: керуючі символи, колізія лапок, потрійні лапки, побудова даних через
`json.dumps` замість ручного екранування, затінення імен, журнали-знімки.

Детальний розбір того, що зроблено, що зламано і куди рухатися далі — у `ANALIZ.md`.
Повний перелік розділів, мапа джерел і прогалини в дослідженні — у `OUTLINE.md`.

## Правила написання розділу

Розділ вважається готовим, якщо містить усі шість блоків:

1. **Що це** — одне-два речення по суті, без води.
2. **Навіщо** — яку задачу розв'язує, коли застосовувати, а коли **не** застосовувати.
3. **Як працює під капотом** — механіка: структури даних, обчислення, вузьке місце, що саме робить
   бібліотека за вас. Найцінніша частина.
4. **Мінімальний робочий приклад Python** — такий, що його можна скопіювати й запустити.
5. **Типові помилки / підводні камені** — конкретні, з поясненням *чому* воно ламається.
6. **Альтернативи** — таблиця порівняння, коли що брати.

Плюс блок **Джерела** з markdown-посиланнями в кінці кожної підтеми.

Оформлення: заголовок теми — рівно `##` (без власного `# H1` і без змісту всередині), підтеми — `###`,
деталі — `####`. Обсяг — 600–1200 рядків. Повні критерії — в `OUTLINE.md`, розділ 7.
