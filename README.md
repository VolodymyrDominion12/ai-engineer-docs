# AI Engineer — довідник українською

Практичний довідник з AI-інженерії для досвідчених Python-розробників. Пояснює не лише «як викликати
API», а й **що відбувається під капотом**: як рахуються токени, чому кеш не влучає, як влаштований цикл
агента, скільки пам'яті з'їдає квантизована модель.

**Зріз даних:** 26 вересня 2026 року.
**Мова:** українська; англійські терміни в дужках при першій згадці.
**Аудиторія:** Python-розробник (≈10 років досвіду), який щойно входить у AI.

---

## Головний принцип проєкту

> **Жодної назви моделі, ціни, назви параметра чи версії бібліотеки «з голови».**

Кожна така деталь підтверджена первинним джерелом — офіційною документацією, сторінкою релізу або
PyPI, — і збережена в `research/`. Це принципово, бо екосистема LLM змінюється швидше, ніж будь-яке
друковане видання: знання моделі «з пам'яті» тут майже завжди застарілі.

Якщо факт не вдалося підтвердити, у тексті так і написано: *«не вдалося підтвердити станом на 09.2026»*.

## Швидкий старт

```bash
git clone git@github.com:VolodymyrDominion12/ai-engineer-docs.git
cd ai-engineer-docs

# Середовище для ноутбуків
python3 -m venv .venv
source .venv/bin/activate

# Мінімум для ноутбуків без GPU (розділи 1–18, 22–25)
pip install -r requirements.txt

# Ключі — лише через .env, ніколи в коді
cp .env.example .env
$EDITOR .env

jupyter lab
```

Ноутбуки **1, 2, 3, 6, 14** виконуються повністю **без жодного API-ключа** — з них і варто починати.
Ноутбуки 19, 20, 21 потребують GPU. Вимоги вказані в першій markdown-клітинці кожного ноутбука.

### Ноутбуки збираються програмно

Ноутбуки не редагуються вручну — вони генеруються через `nbformat`, щоб текст і код не розходилися:

```bash
# Зібрати всі ноутбуки (або вказати конкретний: 03)
python3 tools/build_notebooks.py
python3 tools/build_notebooks.py 03

# Перевірити, що ноутбук справді виконується без ключів
python3 -m nbconvert --to notebook --execute --inplace notebooks/03-tokenizaciya.ipynb
```

Ноутбук, який падає без API-ключа там, де заявлена робота без ключа, — це дефект, а не очікувана
поведінка. Кожен ноутбук закінчується клітинкою самоперевірки з `assert`-ами.

## Як добуваються джерела

```bash
cd ai-engineer-docs

# Трюк .md: багато doc-сайтів віддають чистий markdown замість HTML
python3 fetch.py "https://platform.claude.com/docs/en/docs/about-claude/pricing" 8000 --md
python3 fetch.py "https://developers.openai.com/api/docs/pricing" 8000 --md

# Без --md скрипт витягує текст із HTML (працює майже всюди)
python3 fetch.py "https://qdrant.tech/documentation/search/hybrid-queries/" 8000

# Версії бібліотек — з PyPI, а не «з голови»
curl -s https://pypi.org/pypi/transformers/json | python3 -c "import sys,json;print(json.load(sys.stdin)['info']['version'])"

# Релізи на GitHub без токена
curl -s https://api.github.com/repos/huggingface/transformers/releases/latest
```

Корисні «індекси всієї документації», які віддають перелік усіх сторінок:
`https://developers.openai.com/llms.txt`, `https://platform.claude.com/llms.txt`,
`https://modelcontextprotocol.io/llms.txt`.

**Важливо:** для `transformers`, `datasets` і `peft` документація лежить у файлах `.mdx`, тож запит
`.md` дає 404. Читайте через `raw.githubusercontent.com` з правильним розширенням або через index-файл.

## Правила написання розділу

Розділ вважається готовим, якщо містить усі шість блоків:

1. **Що це** — одне-два речення по суті, без води.
2. **Навіщо** — яку задачу розв'язує, коли застосовувати, а коли **не** застосовувати.
3. **Як працює під капотом** — механіка: структури даних, обчислення, вузьке місце, що саме робить
   бібліотека за вас. Найцінніша частина.
4. **Мінімальний робочий приклад Python** — такий, що його можна скопіювати й запустити.
5. **Типові помилки / підводні камені** — конкретні, з поясненням *чому* воно ламається.
6. **Альтернативи** — таблиця порівняння, коли що брати.

Плюс блок **Джерела** з markdown-посиланнями в кінці кожної підтеми.

Оформлення: заголовок теми — рівно `##` (без власного `# H1` і без змісту всередині), підтеми — `###`,
деталі — `####`. Обсяг — 600–1200 рядків. Повні критерії — в `OUTLINE.md`, розділ 7.

## Ліцензія та походження матеріалів

`research/` містить фрагменти документації третіх сторін (Anthropic, OpenAI, Hugging Face,
Model Context Protocol, Langfuse, Promptfoo, OpenTelemetry, Qdrant, Google, Mistral, DeepSeek).
Ці матеріали належать їхнім правовласникам і збережені виключно як джерела для написання
авторського тексту; кожен файл починається рядком `### SOURCE:` з посиланням на оригінал.

Текст `sections/` і код `notebooks/` — авторські. Ліцензію для них ще належить вибрати.
