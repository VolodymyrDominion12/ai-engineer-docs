## 1. ЯК ЧИТАТИ ДЖЕРЕЛА (обов'язково)

`web_search` повертає лише посилання — їх треба ЗАВАНТАЖИТИ. Є хелпер:

```bash
cd /home/volodymyr/PycharmProjects/ai-engineer-docs
python3 fetch.py "https://developers.openai.com/api/docs/pricing" 8000 --md
python3 fetch.py "https://platform.claude.com/docs/en/docs/about-claude/models/overview" 8000
```

- `--md` додає `.md` до URL. **Багато доків так віддають чистий markdown** — це найкращий спосіб.
  Працює для `developers.openai.com`, часто для `platform.claude.com`, `docs.anthropic.com`.
- Без `--md` скрипт витягує текст із HTML (працює майже всюди).
- Корисні «індекси всієї документації»: `https://developers.openai.com/llms.txt`,
  часто є `llms.txt` / `llms-full.txt` і в інших проєктів — спробуй.
- Для GitHub-проєктів краще читати raw-файли:
  `https://raw.githubusercontent.com/ORG/REPO/main/README.md`
- API GitHub без токена: `https://api.github.com/repos/ORG/REPO/releases/latest`
  (дає актуальну версію бібліотеки й дату релізу).
- PyPI для версій: `https://pypi.org/pypi/PACKAGE/json` → `.info.version`

Зроби **мінімум 12–20 цільових запитів** `web_search` по своїй темі й завантаж **мінімум 10–15 сторінок**.
Не задовольняйся одним джерелом на факт.

## 2. ЩО САМЕ ТРЕБА НАПИСАТИ

Для КОЖНОЇ підтеми, яку тобі дали:

1. **Що це** — одне-два речення по суті, без води.
2. **Навіщо** — яку задачу розв'язує, коли застосовувати, а коли НЕ застосовувати.
3. **Як працює під капотом** — механіка: які структури даних, які обчислення, де вузьке місце,
   що саме робить бібліотека за тебе. Це найцінніша частина.
4. **Мінімальний робочий приклад Python** — такий, що його можна скопіювати й запустити.
   Реальні назви параметрів, реальні сигнатури (перевірені в доках!).
5. **Типові помилки / підводні камені** — конкретні, з поясненням *чому* воно ламається.
6. **Альтернативи** — таблиця порівняння, коли що брати.

## 3. ФОРМАТ ФАЙЛУ

Пиши у файл, який тобі вказано. Структура:

```markdown
## <Номер>. <Назва теми>

<короткий вступ — 2-4 речення, що це і навіщо>

### <Номер>.1 Підтема

...текст...

```python
# код
```

**Типові помилки**
- ...

**Альтернативи**: ...

**Джерела**: [Назва](URL), [Назва](URL)
```

Правила оформлення:
- Заголовок теми — рівно `##` (щоб вставити в загальний документ), підтеми — `###`, деталі — `####`.
- НЕ додавай власний `# H1` і не додавай зміст — його зробить головний редактор.
- Таблиці для порівнянь — обов'язково, де є що порівнювати.
- Код — реальний, з коментарями українською де доречно. Не вигадуй параметри.
- В кінці КОЖНОЇ підтеми або теми — блок **Джерела** з markdown-посиланнями.
- Мова — українська, технічна, для досвідченого Python-розробника (10 років), який
  щойно починає в AI. Терміни англійською в дужках при першій згадці.
- Обсяг: суттєвий. Краще 600–1200 рядків якісного тексту, ніж 200 рядків води.
